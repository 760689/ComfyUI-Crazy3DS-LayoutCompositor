## 2. 核心工作流：多角色合影 / 物体融图（透明 PNG 素材）

**目标**：把**任意物体 / 角色的无底 PNG 抠图**当积木，在画板上摆成一张"合成蓝图"，交给模型融成一张可信的照片（多人合影、人物 + 道具、角色进场景、商品与人）。

这条流水线能成立的关键：画板解决**构图问题**，模型只负责**融合问题**（统一光照、阴影、透视、边缘）。

### 2.1 素材准备

| 素材 | 要求 | 处理 |
|---|---|---|
| 角色 / 人物 | **PNG + alpha，无底最佳** | 已有抠图直接导入；有底图的用 `✂ 图层自由擦除` 就地擦掉背景 |
| 物体 / 商品 / 道具 | 同上，边缘干净 | 残留半透明脏边擦 1–2px |
| 动物 / 家具 / 植物 | 同上 | 注意底边要压到地面线 |
| 场景底板（可选） | 一张有透视的地面/室内图 | 先导入当底图，角色叠在上面 |

> 导入时透明边框会自动裁掉（`autoCropTransparentBorders`），抠图四周留白多少都不影响站位。

### 2.2 操作步骤

1. **先定画板**：顶栏选最终成片的比例与档位（合影常用 `16:9` / `3:4`；成片要 4K 就选 `4K`）。之后切比例素材自动居中，不会被重排。
2. **铺底板（可选）**：场景图拖进画板 → `✥ 移` 拉满 → `↓ 置底`。
3. **逐个导入角色/物体**：`⮮ 导` 多选 / 拖入 / `Ctrl+V`。导入后自动进入 `✥ 移`，新层在最上层。
4. **粗摆站位**（这一步决定成败）：
   - **脚底线对齐**：所有人物的脚 / 物体底边拖到同一条水平线上（合影最容易翻车的点）；
   - **近大远小**：前排人物比后排大 5–15%，纵深感立刻出来；
   - **留缝**：人物之间留 10–30px 空隙，模型更容易分清边界，不易糊成一坨；
   - **朝向**：`⇄ 镜像` 统一成同一侧；中间主角正对镜头。
5. **精修边缘**：`✂ 图层自由擦除` 把抠图残留的脏边 / 白边刷掉；物体悬空就把底边往下压 2–3px"扎进地面"。
6. **融合度微调**：`图层透明度` 85–100%（插入物与环境差异大时略降）；`旋转` 让物体贴合透视方向。
7. **标注补光（可选但很有效）**：`✎ 画` 用灰色低不透明度画一道落点阴影，或用箭头标出光照方向，模型会照着做。
8. **输出**：`image` 接图像编辑 / 融图模型（Qwen-Image-Edit、Flux Kontext、GPT-Image-Edit、任意 img2img 低 denoise）。

### 2.3 Prompt 写法（关键：只描述结果，不描述摆放）

✅ 推荐：

```
把这几个角色合成一张自然的多人合影：
- 统一为室内暖光，同一地面阴影，人物之间光线方向一致；
- 保持每个人的脸、发型、服装细节完全不变；
- 输出一张真实摄影质感的照片，不要拼贴痕迹。
```

❌ 不推荐：`"左边第一个人…右边第二个人…"` —— 站位已由画板决定，再写一遍只会让模型反复改构图。

### 2.4 四类常见场景

| 场景 | 摆法 | 备注 |
|---|---|---|
| **多人合影** | 一排站定、脚底对齐、近大远小；主角居中略大 | denoise 0.35–0.55，只融光影 |
| **人物 + 道具** | 物体贴手部 / 落座位置，透明度 95%+ | 接触面与身体留 1–2px 交叠更自然 |
| **角色进场景** | 先铺场景做底层，再放角色，按场景透视线定高度 | 场景有地平线时，脚底压在那条线上 |
| **商品矩阵 / 换装对比** | 用 `━ 横排` / `田 网格` 规整排列 | 不融图时当纯排版板用 |

### 2.5 抠图 / 镂空（把有底图变成无底图）

1. 导入图片 → `✥ 移` 选中它。
2. 点 `✂ 图层自由擦除`，`擦除粗细` 调到 15–60px，沿背景涂抹。
3. 擦的是**像素透明**（`destination-out`），不是涂白 —— 叠到别的底图上不会出现白块。
4. 边缘细节换小笔刷（5–15px）收边；擦错了 `Ctrl+Z`。
5. 顶栏底色切 `透明` + `☑︎存`，可把这个抠图**导出成带 alpha 的 PNG 素材**复用。

> 与画笔的「橡皮擦」区分：橡皮擦只擦**手绘笔触**，`图层自由擦除` 擦的是**图片图层的像素**。

## 3. 工作流 A：手绘示意 / 区域标注

**目标**：让编辑模型知道"改哪里、改成什么"。

1. 顶栏 `✥ 移` 保证不在画笔状态（或直接点 `✎ 画` 进入画笔）。
2. 素材来源任选：
   - 把原图拖进画板，或 `Ctrl+V`；
   - 上游已有出图 → 连 `images` 后点 `✜ 读`。
3. 素材导入后节点自动切到 `✥ 移`，先在画板上把它摆好位（选中拖动；四角手柄缩放；`Shift` 多选一起动）。
4. 点 `✎ 画` → `⮻功能参数` 里调标定：
   - 粗细（1–150px）：圈区域用 8–16px，写字用 24–48px；
   - 不透明度（5–100%）：压在照片上标注建议 60–100%；
   - 颜色：7 色预设或取色器；要精确匹配就用「吸管」在画面上取。
5. 在画板上画：红圈 = 目标区域、箭头 = 变换方向、`1 2 3` = 分区编号、文字 = 目标字形。
6. 画完点顶栏 `✥ 移`（或**在画板右键**）退出画笔，避免误触继续落笔。
7. 下游接编辑模型，prompt 里对应说明（例："把红圈区域内的外套改成米白色，保持 1 号区域的人物姿态不变"）。

**要点**

- 手绘与图片**分层存储**：移动图片不会带着笔触跑，清除手绘也不会动图片。
- 标注写错了：`Ctrl+Z` 逐笔撤销，或 `橡皮擦` 局部擦，或 `清除手绘` 一次清空笔触。
- 想保留标注又要重排版：直接点排版按钮，笔触层不动。

## 4. 工作流 B：多图导入拼贴

**目标**：把 2–8 张参考图拼成一张有设计的画板。

### 3.1 导入

| 方式 | 操作 | 备注 |
|---|---|---|
| 本地导入 | 顶栏 `⮮ 导` → 多选文件 | 支持 `image/*` |
| 拖拽 | 直接把文件拖到画板内 | 支持一次拖多个 |
| 粘贴 | 悬停/选中节点后 `Ctrl+V` | 从截图工具、浏览器直接粘贴 |
| 上游 | 连 `images` → `✜ 读` | 上游多张时批量载入并阶梯错位 |

> 导入带透明边的 PNG 会自动裁掉透明边框（扫描整张 alpha，取非透明包围盒），拼图不留空档。

### 3.2 手动粗排（可选，推荐）

- `✥ 移` + 拖拽，把主图放左边、细节图堆右边 —— **不用对齐**。
- 完成后点 `✨ 对齐优化`：它会读你摆出来的"大格局"，只负责对齐边缘、拉平尺寸、统一 4px 缝隙。

### 3.3 一键满铺

- 有主视觉（人像 / 商品主图）：`📰 焦点`。当前选中的图层会成为主图；不满意就**再点一次**（副图顺序随机洗牌，每次排法不同）。
- 无明显主次：`田 网格`。3–8 张有预置最优分割候选，自动选覆盖率最高的；连点也能换排法。
- 统一长条：`━ 横排`（等高）或 `┃ 竖排`（等宽）。
- 只想排**选中的几张**：`Shift` 多选后点排版按钮即可只作用于选中层。

### 3.4 微调

- 单层微移：`✥ 移` 拖动（`Alt` 在重叠处下钻到下面那层）。
- 遮盖关系：`↑ 置顶` / `↓ 置底`。
- 融合度：`图层透明度` 0–100%（支持多选统一）。

## 5. 工作流 C：读取上游结果并按宫格排版

**目标**：上游一次出 4/6/8 张（批次或多宫格），直接在画板上排版定稿。

1. 上游图像节点（SaveImage / PreviewImage / 任意 `IMAGE` 输出）连到本节点 `images`。
2. **先跑一次上游**（`✜ 读` 依赖 ComfyUI 的 `nodeOutputs`，没跑过会提示"上游节点尚未运行"）。
3. 点 `✜ 读`：上游输出几张就载入几个独立图层（自动按 26px 阶梯错位，方便分辨）。
4. 排版：
   - 想要规整宫格 → `田 网格`（4 张会给 `[2,2]`；宽画板给 `[4]`；竖画板给 `[1,2,1]`）；
   - 想要有主次 → 先点中主图，再 `📰 焦点`，反复点直到满意；
   - 已经是宫格图但被切成单张、想恢复原样 → `━ 横排` / `┃ 竖排` 按原始顺序重排。
5. `☑︎存` 存成一张大图，或直接把 `image` 连给下游。

**说明**：`✜ 读` 是**追加**而非替换 —— 想换一批，先 `⮿清` 或逐层 `Delete`。

## 6. 工作流 D：裁剪、镂空与透明素材

### 5.1 比例裁剪

1. `✥ 移` 选中目标图层。
2. 参数卡 `图层裁剪` → 点 `1:1 / 4:3 / 3:4 / 16:9 / 9:16`：立刻在该层最大内接范围内生成锁定比例的裁剪框。
3. 拖框移动 / 拖八向手柄缩放（比例锁定下缩放手柄保持比例），`Shift` 用于自由模式锁比例。
4. `Enter` 或 `✔ 应用裁剪` 确认；`Esc` / `✕ 取消` 放弃。

> 裁剪是**真实的像素裁剪**（换掉图层画布、改写 `origW/origH`），并且会重算图层在画面上的位置与尺寸，让裁剪前后的视觉位置**保持一致**，不会突然跳到别处。裁剪可撤销。

### 5.2 自由裁剪

`⛶ 自定义裁剪` → 拖出任意框；已在裁剪模式中再点一次 = 解除比例锁，变自由拖拽。

### 5.3 图层镂空

1. 选中图层 → `✂ 图层自由擦除`。
2. `擦除粗细` 1–150px，在图层上涂抹即擦成**透明像素**（`destination-out`），不是画白色。
3. 退出：再点按钮或画板右键。

用途：挖窗口/光圈/剪影、把背景某块变透明、做不规则遮罩素材。

### 5.4 透明底导出

顶栏底色选 `透明`，`☑︎存` 导出的 PNG 带 alpha 通道（后端合成时透明底会转成白底再喂下游，前端导出保留 alpha）。

## 7. 工作流 E：一键存图与传输

### 6.1 存图

- `☑︎存`：把 `exportCanvas`（当前档位最高分辨率）以 PNG 下载，文件名 `crazy3ds_<比例>_<档位>_<毫秒时间戳>.png`。

### 6.2 传输给下游（自动）

| 时机 | 动作 |
|---|---|
| 任何编辑停止 600ms 后 | 合成并上传 `node_<id>.png`（手绘/图层有改动才补传对应层） |
| 排队工作流前 | `app.queuePrompt` 钩子对所有本节点调用 `forceBakeAndUpload()`，确保最新画面已落盘 |
| 下次执行节点 | 后端读 `input/crazy3ds_temp/node_<id>.png` → 转 tensor |

**为什么需要"强制烘焙"**：ComfyUI 的执行顺序和 UI 编辑是异步的。若只靠 debounce，快速拖动后立刻点"运行"可能把上一帧发下去。钩子保证"你看到的 = 模型拿到的"。

### 6.3 清空

`⮿清`：清图层 + 笔触 + 内存池 + 调用 `POST /crazy3ds/clear_temp` 删除临时目录内文件。**此操作本身进历史，可 `Ctrl+Z` 撤回画板内容**（临时 PNG 需重新烘焙）。

## 8. 排版算法详解

所有排版统一前提：`GAP = 4`（严格 4px 微缝），**只用素材原生宽高比 `r = W/H` 计算**，不做任何裁切或非等比拉伸。

### 7.1 横排 `row`
- 按当前 X 排序；`sumAspect = Σr`；可用宽 `wAvail = targetW - (N-1)·GAP`。
- 理想高度 `H = min(targetH, wAvail / sumAspect)`；总宽 `totalW = H·sumAspect + (N-1)·GAP`。
- 整体水平居中：`startX = (targetW - totalW)/2`，垂直居中 `startY = (targetH - H)/2`。
- 每张宽 `H·r`，高度统一 `H`。

### 7.2 竖排 `col`
- 与横排对偶：`sumInvAspect = Σ(1/r)`；`H = targetH - (N-1)·GAP`；宽 `W = min(targetW, H/sumInvAspect)`；每张高 `W/r`。

### 7.3 焦点 `hero`
1. **主图确定**：优先当前选中层，否则面积（`w·h`）最大的层。
2. **副图随机洗牌**（Fisher–Yates），用于"多次点击探索不同排法"。
3. 宽画板（`targetW ≥ targetH`）：主图占一栏，副图分 `numCols ∈ {1, 2, (极宽时 3)}` 栏；对每种栏数做代数求解：
   - 列内纵向堆叠的"逆宽高比之和" `K_i = Σ(1/r)`，总需求高度
     `H_req = (targetW - gapCorrection) / (rHero + Σ(1/K_i))`
   - 覆盖率 `coverage = totalW · H_actual`，取覆盖率最大的方案；
   - 主图放在**原位置所在的那一侧**（`hl.x > targetW/2` 则靠右），保持用户视觉意图。
4. 竖画板：主图占一行，副图分行 `numRows ∈ {1, 2, (极竖时 3)}`，同法取覆盖率最优。

### 7.4 网格 `grid`
1. 排序：有选中层则它排第一，其余随机；否则全部随机。
2. `N ≤ 2` 直接退化为横排/竖排。
3. 候选分割（按 N 与画板长宽比）：

| N | 候选 |
|---|---|
| 3 | `[2,1]`、`[1,2]`；极宽画板加 `[3]` |
| 4 | `[2,2]`；极宽加 `[4]`；极竖加 `[1,2,1]` |
| 5 | 横版 `[3,2] [2,3]`；竖版 `[2,1,2] [1,2,2] [2,2,1]` |
| 6 | `[3,3]`；竖版加 `[2,2,2]` |
| 7 | `[4,3] [3,4] [2,3,2]` |
| 8 | `[4,4] [3,2,3]` |
| >8 | `c = round(sqrt(N·targetW/targetH))` 自适应分块 |

4. 每个方案：行宽需求和 `sumInvS = Σ 1/S_j`（`S_j` 为行内比例和），修正 4px 缝隙后求 `W_grid`：
   - 若 `W_grid ≤ targetW` → 以画板高为基准；否则以画板宽为基准并求 `H_total`。
   - 得分 `score = W_grid · H_total`，取最大者；整体居中。

### 7.5 对齐优化 `tidy`
1. **拓扑聚类（保留你的大格局）**
   - 纵向分栏：按中心 X 排序，逐张尝试并入已有列 —— 要求与该列任一图在 Y 轴重叠 `< 0.35·min(h)`，且中心距 `< max(0.16·targetW, 0.75·列内最大宽)`；
   - 横向分行：对偶规则（X 轴重叠 + 中心 Y 距）。
   - 判据 `isColPreferred = 存在高度 > 0.65·targetH 的贯通大图 || 列数 ≤ 行数`。
2. **代数拉平**
   - 分栏：所有列统一高度 `H_opt`，同列内统一列宽，四边顶满；
   - 分行：对偶（统一宽 `W_opt`、行高一致）。
3. `N = 1` 时退化为"单图最大内接居中"。

> 为什么不用简单网格？因为用户手动摆的往往是"1 大 + 3 小"、"上 2 下 3"这类非均匀结构，硬套网格会毁掉意图。tidy 的目标是**只规整、不重构**。

## 9. 图层交互模型

### 8.1 命中判定（`checkLayerHitTest`）
- 先把画板坐标转换到图层的**去旋转局部坐标**（`toLayerBoxCoords`，反向旋转 `-rotation`）；
- 在局部坐标里判是否落在 `[-w/2, w/2] × [-h/2, h/2]`；
- 再换算到图层像素坐标读 `alpha`，得到 `hasPixel`（是否打在非透明像素上）。
- 选择时优先 `hasPixel` 的图层（所以点在透明区域会"穿"到后面的图），`Alt` 在该候选列表里循环下钻。

### 8.2 多选与整体操作
- `selectedLayerIndices` 为多选集合，`selectedLayerIndex` 为"主选层"（属性面板、裁剪、旋转滑块作用于它）。
- 排版、透明度、置顶/置底、删除均支持多选；排版时选中 ≥2 张则**只排选中的**。

### 8.3 变换
- 拖动：`drag_layer`，多选时记录每层初始矩形整体平移，位移**夹紧**在画板内。
- 四角缩放：`resize_layer`，从对角/中心按原始宽高比约束。
- 旋转：顶部手柄拖动改角度，`Shift` 吸附 15°；参数卡滑块同步。
- 镜像：`flipH` 布尔，渲染与光标判定都考虑翻转（`canvasPosToDrawBox` 里乘 `-1`）。

## 10. 状态、撤销与持久化

### 9.1 历史（15 步）

| 记录类型 | 内容 | 产生时机 |
|---|---|---|
| `draw` | 手绘层 `ImageData` | 每一次落笔、橡皮、清除手绘 |
| `layer` | 单个图层像素 `ImageData` | 图层自由擦除 |
| `snapshot` | 图层数组引用 + 几何/旋转/镜像/透明度 | 拖动、缩放、旋转、透明度、层级、增删、排版 |
| `canvas` | 裁剪前后的画布与几何 | 应用裁剪 |
| `layout` | 全图层矩形 | 排版（兼容式记录） |

- 拖拽类使用 `beginLayerSnapshot()` / `commitLayerSnapshot()`：**按下不记，真位移才记**，撤销不会白走一步。
- 任何新操作清空 `redoStack`。

### 9.2 持久化层级

| 层 | 内容 | 生命周期 |
|---|---|---|
| `node.properties` | `ratio / scaleTier / bg_color / has_draw / layers[]`（几何 + 原图尺寸） | 随工作流 JSON 保存 |
| `window._crazy3ds_memory_store[nodeId]` | 图层对象（含 canvas 引用） | 当前浏览器会话 |
| `input/crazy3ds_temp/*.png` | 合成图 / 手绘层 / 各素材层 | 磁盘，直到 `⮿清` |

**恢复顺序**：内存池 → 节点 `properties` + `/view` 拉 PNG → 若都没有则空画板。恢复后自动 `syncDisplayCanvasLayout()` 重算显示比例。

### 9.3 尺寸变化的坐标系处理

- 切**档位**（tier）：`scaleFactor = newW/oldW`，所有图层 `x/y/w/h` 同乘，笔触层直接重绘缩放 → 排版关系不变、清晰度提升。
- 切**比例**：图层 `x/y` 平移 `(newW-oldW)/2, (newH-oldH)/2`（居中），`h = w/aspect` 重新按原生比例修正 → 不挤压变形；笔触层按偏移贴回。

## 11. 后端接口与数据契约

### 10.1 节点定义

```python
class Crazy3DS_LayoutCompositor:
    INPUT_TYPES:  required { image_name: STRING(default "") }
                  optional { images: IMAGE }
    RETURN_TYPES = ("IMAGE",)   RETURN_NAMES = ("image",)
    FUNCTION = "execute"        CATEGORY = "Crazy3DS"
```

`execute(image_name, images)` 逻辑：

1. `image_name` 非空且在 `input/` 存在 → 打开 → `ImageOps.exif_transpose` → RGBA 合成到白底 → RGB → `np.float32/255` → `torch[None,...]`；
2. 否则若 `images` 有值 → 原样透传；
3. 都没有 → 1024×1024 白图兜底。

`IS_CHANGED` 返回 `f"{mtime}_{size}"` → 画板文件变了必然重算，不会命中缓存。

### 10.2 HTTP 路由

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/crazy3ds/clear_temp` | 删除 `input/crazy3ds_temp` 下所有文件，返回 `{"status":"success"}` |

### 10.3 前端钩子

| 钩子 | 作用 |
|---|---|
| `app.registerExtension({ name: "Crazy3DS.LayoutCompositor", beforeRegisterNodeDef })` | 只为 `Crazy3DS_LayoutCompositor` 注入 UI |
| `onNodeCreated` | 构建 DOM（顶栏 + 画板 + 参数卡），绑定全部事件 |
| `onRemoved` | 解绑全局监听、断开 `ResizeObserver`、清定时器 |
| `onResize` | 重算字号与显示布局 |
| `app.queuePrompt` 包装 | 队列前统一 `forceBakeAndUpload()` |
| `nodeInstance.forceBakeAndUpload` | 暴露给外部/其它节点手动触发烘焙 |

## 13. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 节点显示但没画板 / 一片空白 | 前端 JS 未加载（浏览器缓存、`WEB_DIRECTORY` 不对） | `Ctrl+F5` 强刷；确认 `web/crazy3ds_compositor.js` 存在；看控制台报错 |
| `✜ 读` 提示"请先将上游图像节点连接" | `images` 插槽没连线 | 连上游 `IMAGE` 输出 |
| `✜ 读` 提示"上游节点尚未运行" | `nodeOutputs` 里没有该节点输出 | 先执行一次上游 |
| 读取只进了一张 | 上游是单张输出 | 用批次 / 多图输出节点 |
| 下游图与画板不一致 | 直接改了 `image_name`，或上传失败（权限/磁盘满） | 保留 `image_name` 自动值；查 ComfyUI 控制台 |
| 裁剪后图层位置跳了 | 旧版本 bug | v1.0.0 已修正：裁剪保持视觉位置不变 |
| 8K 拖动卡 | PNG 编码耗时 | 编辑期用 2K，定稿再切 4K/8K |
| 刷新后要等 | 从 `/view` 拉回大图 | 正常；可用较低档位编辑 |
| 多节点后越来越卡 | 旧版未解绑监听（修复于 v1.0.0） | 升级到 v1.0.0+ |

## 14. 性能与画质建议

| 场景 | 建议 |
|---|---|
| 构思 / 排版调整 | `2K` + `透明`，交互最跟手 |
| 最终交付（人像/商品） | `4K`，足够 300dpi A4/海报 |
| 大画幅 / 裁切余量大 | `8K`（约 4×2K 像素量），导出前先 `☑︎存` 备份 |
| 图层很多（>10） | 交互期先 `━ 横排` 规整，减少重叠命中计算；关闭不必要的图层透明度调节 |
| 素材本身分辨率低 | 不要用 4K/8K 硬放大（导入层按原图像素绘制，画板大只是留更多空间） |
